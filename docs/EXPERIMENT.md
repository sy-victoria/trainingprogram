# 实验协议

## 固定条件

- 官方 Qwen3.5-0.8B、2B、4B 的具体 revision 见 `configs/versions.json`。
- 原始 safetensors dtype 直读文件头记录；支持 BF16 为主且包含 F32 等辅助张量的来源，不支持混合 F16 权重静默转换。
- 文本 GGUF BF16 与由同一 BF16 GGUF 自行量化的 Q4_K_M 对照；不测视觉能力，不宣称 GGUF 转换与 Transformers 逐位相同。
- Q4_K_M 是混合量化，不是每个张量都 4-bit；不使用基准题目校准，不使用 importance matrix。
- 同一 llama.cpp 提交、GPU、8192 上下文、1 个并行 slot、8 个 CPU 线程；temperature=0、seed=2026、最大输出2048 tokens、关闭 thinking。固定设置不等于跨硬件逐位确定性。
- HumanEval+ v0.1.10：任务ID排序后用固定随机种子打乱，smoke取前2题，subset取前30题，full取全部164题。保存数据内容哈希与完整任务清单。
- 只发送问题 prompt，不发送 canonical_solution、隐藏测试或判题反馈；每题仅一次采样。

## 成绩与错误

HumanEval+ 通过要求 base 和 plus 均通过。复用固定版本 EvalPlus 的 `trusted_exec` 和 `untrusted_check`，不使用要求全题集的 evaluate 入口。每题独立容器；判题墙钟限制180秒，官方逐用例下限0.2秒、参考耗时倍率4。

格式错误、生成请求错误、中断后未完成的请求均保留在分母，不默默重试；重做整个实验需新运行ID。截断单独标记，仍对已有代码判题，不预先判为失败。基础设施错误和缺少判题数据导致“未完成”，不输出 pass@1。

配置或样本被修改时拒绝混用结果。进程在请求开始后退出会把该题标记为 interrupted，下一次不重新采样。已完成题目的原始响应不覆盖。

30题子集只用于探索；报告通过数和分母，并给出逐题回归/改善案例。不能凭少量差异推断普遍性能优劣。

## 速度和资源

五个固定提示，预热一次、重复三轮，单独记录首输出片段延迟、端到端延迟、输出 tokens/s。当前 tokens/s = completion_tokens / 总请求时间，包含 prefill 和HTTP开销，**不是纯 decode throughput**。服务的前缀缓存可能为热缓存；不同生成长度仍可能影响比较。

资源每秒采样：llama-server进程RSS、GPU 0整卡已用显存。空缺表示不可测，不填0；采样可能漏掉瞬时峰值。不要并行运行Agent、其他推理服务或另一个评测任务。

配对比较要求同模型revision、数据哈希、题目集合、推理配置、判题镜像与硬件记录相同。变化量定义为 `量化 pass@1 - BF16 pass@1`，乘100得到百分点；显存减少不代表必然加速。

## 三天任务

第一天完成环境诊断、0.8B冒烟与Agent最小闭环；第二天完成恢复审批、六组生成和可用的隔离判题；第三天补齐判题、失败分析、框架小示例与演示录像。

Qwen3.8、9B、27B及更大规模未纳入本次交付，不能把本次报告描述为原作业全部规模已完成。
