# 实验记录（2026-11-16）

## 量化对照

Qwen3.5 三个规模各运行 BF16 GGUF 与 Q4_K_M；BF16 保留来源权重精度，推理后端均为锁定版本的 llama.cpp。这是相同后端内的量化对照，并非 Transformers 原生推理与 llama.cpp 的比较。

HumanEval+ 固定种子 2026 抽取 30 题，六组共享题目 ID，每题只生成一次，temperature=0，最大输出 2048 token，关闭 thinking，服务上下文 8192。每组均完成 30 次生成及隔离判题，基础设施错误为 0。正式结果不混入两题 smoke。

| 模型 | BF16 通过 | Q4_K_M 通过 | pass@1 差异（量化−原版） | 文件缩小 |
|---|---:|---:|---:|---:|
| 0.8B | 8/30（26.67%） | 7/30（23.33%） | −3.33 个百分点 | 64.86% |
| 2B | 12/30（40.00%） | 12/30（40.00%） | 0.00 个百分点 | 66.05% |
| 4B | 25/30（83.33%） | 22/30（73.33%） | −10.00 个百分点 | 67.51% |

2B 总分相同不意味着输出没有变化：HumanEval/102、71 由通过变为失败，104、69 由失败变为通过。4B 的 3 道回归为 102、117、26，没有反向改善。0.8B 有 4 道回归（139、58、61、99）与 3 道改善（12、54、69）。这些是配对题目的观察，不能推断所有任务上的量化损失。

0.8B BF16 有 1 次截断/提取错误，Q4_K_M 有 2 次；这些计入失败，没有删除或重新采样。2B、4B 无截断和提取错误。因此 4B 的差异不能用输出长度上限解释。30 题中每道题对应 3.33 个百分点，样本较小，不代表完整基准排名。

逐题检查 4B Q4_K_M 的三项回归可见具体语义错误：102 把区间端点用 `min/max` 排序，错误接受反向区间；117 把所有英文字母都定义成元音，使辅音集合为空；26 保留了重复值的首次出现，而题目要求彻底删除所有出现超过一次的值。这些代码完整且语法有效，说明失败发生在需求理解或实现逻辑。它们是量化配置下观察到的输出变化，单次实验不足以定位到某层权重量化误差的因果机制。

## 框架真实调用

Qwen-Agent 与 Deep Agents 均连接同一份 4B BF16（模型别名 `tp-773e6a3aa94e29d8`），读取相同的 `solution.py`，正确指出 `range` 不包含平方根边界，并建议 `+1`。两者均实际调用读取工具、正常退出，无超时；单次端到端耗时分别为 10.72 秒、10.37 秒，包含 Python 启动开销，不据此判断框架性能优劣。

主 LangGraph 实现另含文件搜索、补丁、测试、SQLite checkpoint、预算与审批。两个对比示例仅验证读取与建议，不可把它们算作完整 SWE Agent 修复成功率。具体机制差异见 [框架对比](FRAMEWORKS.md)。

## 真实 Agent 审查与恢复

4B BF16 三项任务均已生成补丁并持久化暂停。审批方式为用户授权的**代理审批**，不是用户逐项人工批准。审查批准质数平方根边界与平均值空列表补丁；拒绝首次去重补丁，因为使用 `set` 违反支持列表等不可哈希元素的要求。模型随后改用列表查重，经再次审查批准，从已有 SQLite checkpoint 恢复。

三项任务均以 `finished` 结束，并通过恢复原始公开测试、加入模型未见验收测试后的隔离验收，每项 3 个测试。去重任务共使用 10 次模型调用，未增加预算。这是三个小型自建 Python 任务上的 3/3，不是 SWE-bench 成绩，也不是无人干预成功率。代理反馈对去重任务的成功有贡献，不能归为模型一次自主修复成功。

## 复现与范围

结果包保存每组配置、固定题目 ID、原始模型回答、提取代码、逐题判题、速度记录、模型 revision/哈希与运行源码快照。隔离执行使用经过真实机制测试的 bubblewrap + systemd 限制，没有无隔离执行回退。模型权重不进入结果包或 Git。

Qwen3.8、更大规模、完整 HumanEval+、更多随机种子与重复 Agent 试验为后续工作。本记录的成绩为真实模型实测；模拟机制测试不计入模型成绩。代码版本、来源快照与实验配置以结果包记录为准。
